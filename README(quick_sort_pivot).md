
# Quick Sort 피벗 선택 방식 성능 비교

## 1. 과제 개요

동일한 무작위 정수 배열에 대해 세 가지 피벗 선택 방식(첫 번째 원소, 무작위 원소, Median-of-Three)을 적용하고, 정렬 중 발생하는 **데이터 값 비교 횟수**를 측정한다. 보너스로 Median-of-Three를 사용하는 재귀적 퀵 정렬과 반복적 퀵 정렬의 실행시간도 비교한다.

- 언어: C (C11)
- 정렬 순서: 오름차순
- 데이터 범위: `0~1,000,000` (중복 허용)
- 데이터 크기: `1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000`
- 분할 방식: 세 피벗 전략 모두 동일한 Lomuto partition 사용
- 난수 시드: 각 데이터 크기별 고정 시드 사용

## 2. 구현 내용

### 2.1 피벗 선택

1. **First Element**: 현재 구간의 첫 번째 원소를 피벗으로 선택한다.
2. **Random Pivot**: 현재 구간에서 `rand()`로 임의의 위치를 선택한다. 분할이 실행될 때마다 새 위치를 선택한다.
3. **Median-of-Three**: 현재 구간의 첫 번째, 가운데, 마지막 원소 중 값의 중앙값을 선택한다. 산술평균이 아니라 세 값의 크기 순서에서 가운데 값이다.

세 방법은 피벗 위치 선택만 다르며, 피벗을 끝으로 옮긴 뒤 동일한 Lomuto 분할을 수행한다. 분할에서는 `a[j] <= pivot` 비교를 사용한다.

### 2.2 비교 횟수 계산 기준

- 분할 중 배열 원소와 피벗 값을 비교할 때마다 1회 증가시킨다.
- Median-of-Three에서 중앙값을 고르기 위한 데이터 값 비교도 횟수에 포함한다.
- 인덱스 비교, 반복문 조건, 범위 검사, 난수 생성, 데이터 교환은 포함하지 않는다.
- 정렬 후 오름차순 여부 검사는 비교 횟수에 포함하지 않는다.

### 2.3 재귀적 퀵 정렬의 재귀 깊이

재귀 버전은 작은 쪽 부분 배열을 재귀 호출하고 큰 쪽 부분 배열은 반복문으로 처리하는 꼬리 재귀 최적화 형태로 작성했다. 분할 결과와 비교 횟수는 일반적인 재귀 퀵 정렬과 같지만, 한쪽으로 치우친 분할에서 C 호출 스택이 과도하게 깊어지는 것을 방지한다.

### 2.4 반복적 퀵 정렬

보너스 구현은 `Range` 구조체 배열을 명시적 스택으로 사용한다. 재귀 버전과 동일한 Median-of-Three 선택 함수 및 Lomuto 분할 함수를 공유한다. 더 작은 구간은 즉시 처리하고 더 큰 구간을 스택에 넣어 스택 사용량을 제한한다.

## 3. 컴파일 및 실행

GCC 또는 Clang이 설치된 환경에서 다음 명령을 실행한다.

```bash
gcc -O2 -std=c11 -Wall -Wextra -pedantic quick_sort_pivot.c -o quick_sort_pivot
./quick_sort_pivot
```

Windows의 MinGW 환경에서도 동일한 C 소스를 컴파일할 수 있다.

## 4. 실험 결과

아래 값은 제공된 코드의 한 번의 실행 결과다. 난수 시드를 고정했으므로 같은 C 라이브러리와 실행 환경에서는 결과가 재현된다. `rand()` 구현이 다른 운영체제/컴파일러에서는 Random Pivot 결과가 달라질 수 있다.

| 데이터 크기 | First Element | Random Pivot | Median-of-Three |
|---:|---:|---:|---:|
| 1,000 | 11,806 | 10,232 | 10,534 |
| 2,000 | 24,789 | 25,825 | 23,390 |
| 4,000 | 55,554 | 51,788 | 51,674 |
| 8,000 | 131,777 | 116,824 | 115,492 |
| 16,000 | 264,129 | 253,363 | 243,744 |
| 20,000 | 326,853 | 334,838 | 320,178 |

### 결과 분석

1. **데이터 크기 증가**: 데이터 크기가 커질수록 세 방식 모두 비교 횟수가 증가했다. 무작위 데이터에서 전체적인 증가 양상은 평균적인 퀵 정렬의 `O(n log n)` 특성과 비슷하다. 다만 피벗 위치와 분할 결과에 따라 실제 비교 횟수는 달라진다.
2. **First Element**: 첫 원소가 매번 좋은 피벗이라는 보장이 없다. 입력이 이미 정렬되었거나 역순에 가까운 경우 분할이 한쪽으로 치우쳐 비교 횟수가 `O(n^2)` 수준으로 증가할 수 있다. 무작위 입력에서는 첫 원소도 우연히 괜찮은 피벗일 수 있지만, 실험에서는 대체로 다른 두 방법보다 비교 횟수가 많았다.
3. **Random Pivot**: 피벗을 무작위로 선택하면 입력의 기존 순서에 덜 좌우되고 극단적으로 불균형한 분할이 반복될 가능성을 낮춘다. 다만 매번 좋은 분할을 보장하지는 않으므로 실행 및 난수열에 따라 Median-of-Three보다 비교 횟수가 많을 수 있다. 실제로 2,000개와 20,000개에서는 세 방법 중 비교 횟수가 가장 많았다.
4. **Median-of-Three**: 구간 양 끝과 가운데의 값을 살펴 중앙값을 선택하므로 극단적인 값이 피벗이 되는 경우를 줄이는 데 도움이 된다. 중앙값 선택 자체의 비교 비용은 추가되지만, 이후 분할이 더 균형 잡히면 전체 비교 횟수를 줄일 수 있다. 이번 결과에서는 2,000개부터 20,000개까지 가장 적은 비교 횟수를 기록했다.
5. **종합**: 이번 고정 데이터 실험에서는 Median-of-Three가 가장 안정적으로 좋은 결과를 보였다. 다만 데이터 분포와 난수 시드에 따라 Random Pivot이 더 적은 비교 횟수를 기록할 수도 있다. 따라서 한 번의 실험 결과만으로 모든 입력에서 항상 한 방식이 우수하다고 단정할 수는 없다.

## 5. 보너스: 재귀적 vs 반복적 퀵 정렬

- 데이터 크기: 10,000
- 피벗: Median-of-Three
- 동일한 원본 배열을 사용하고, 매 반복마다 정렬 전 복사본을 준비한다.
- 배열 복사와 워밍업은 측정에서 제외한다.
- 각 정렬 실행을 `clock()`으로 측정하고 30회 평균을 출력한다.

| 구현 | 평균 실행시간 |
|---|---:|
| Recursive Quick Sort | 0.585233 ms |
| Iterative Quick Sort | 0.457500 ms |

### 실행시간 분석

이번 실행에서는 반복적 퀵 정렬이 재귀적 퀵 정렬보다 짧은 평균 실행시간을 보였다. 반복적 구현은 함수 호출과 복귀에 따른 호출 스택 관리 비용을 줄일 수 있다. 반면 명시적 스택을 직접 관리하고 범위를 push/pop하는 비용이 추가되므로 모든 환경에서 반복적 방식이 반드시 빠른 것은 아니다. 컴파일러 최적화, CPU, 운영체제, 시스템 부하 및 타이머 해상도에 따라 결과가 달라질 수 있다. 특히 측정 시간이 매우 짧으므로 시간 값은 참고용이며, 여러 번 실행해 경향을 확인하는 것이 좋다.

> 참고: 실행시간 표는 Linux x86_64, GCC 14.2.0, `-O2` 환경에서 측정한 예시다. 다른 컴퓨터에서 실행하면 시간이 달라질 수 있으며, 프로그램이 출력하는 값이 해당 환경의 실제 측정값이다.
