
# Quick Sort vs. AVL Tree Sort 성능 비교

## 1. 실험 목적

동일한 무작위 정수 데이터에 대해 Quick Sort와 AVL Tree Sort를 적용하고, 초기 정렬과 이후 삽입·삭제를 모두 포함한 전체 작업의 실행시간, 데이터 값 비교 횟수, 데이터 이동 횟수, 메모리 사용량을 비교한다.

## 2. 실행 환경 및 실행 방법

- 언어: C (C11)
- 컴파일러: GCC
- 컴파일 명령:
  ```bash
  gcc -O2 -std=c11 -Wall -Wextra -o quick_avl_compare quick_avl_compare.c
  ```
- 실행:
  ```bash
  ./quick_avl_compare
  ```
- 난수 시드: `20261115` (동일한 실행 환경에서 결과 재현을 위한 고정 시드)
- 초기 데이터 범위: -50,000 ~ 50,000 (중복 허용)
- 삽입·삭제 값 범위: -50,000 ~ 50,000 (중복 허용)

## 3. 구현 방법

### 3.1 Quick Sort + 정렬 배열

- Quick Sort의 피벗은 **Median-of-Three(첫 원소, 가운데 원소, 마지막 원소 중 중앙값)** 방식으로 선택했다.
- Quick Sort로 배열을 오름차순 정렬한 뒤에도 배열을 유지한다.
- 삽입은 선형 탐색으로 삽입 위치를 찾고, 뒤쪽 원소를 한 칸씩 이동한 다음 값을 저장한다.
- 삭제는 선형 탐색으로 첫 번째 일치 값을 찾고, 뒤쪽 원소를 한 칸씩 앞으로 이동한다.
- 중복 값은 배열에 여러 원소로 저장하며, 삭제 시 첫 번째 일치 원소 하나만 제거한다.

### 3.2 AVL Tree Sort

- 원본 데이터를 AVL 트리에 하나씩 삽입한다.
- 중복 값은 별도의 노드를 계속 만들지 않고 해당 노드의 `count`를 증가시키는 방식으로 저장한다.
- 중위 순회(Inorder Traversal)를 통해 오름차순 결과를 생성·검증한다.
- 삽입과 삭제는 AVL 트리에서 직접 수행하며, 높이 차이에 따라 LL, RR, LR, RL 회전을 적용한다.
- 삭제 시 중복 개수가 2개 이상이면 `count`만 1 감소시킨다. 마지막 원소를 삭제할 때만 노드를 제거한다.
- 자식이 둘인 노드를 삭제할 때는 오른쪽 서브트리의 중위 후속자 값을 복사하고 후속자 노드를 제거한다.

### 3.3 동일한 입력 및 연산 보장

- 각 데이터 크기마다 원본 정수 배열을 한 번만 생성한다.
- Quick Sort 배열과 AVL 트리는 동일한 원본 배열을 사용한다.
- 연산 목록도 한 번만 생성한 뒤 두 자료구조에 동일한 순서와 동일한 값을 적용한다.
- `rand() % 2` 결과로 삽입 또는 삭제를 결정하고, 실제 처리 값은 별도의 난수 호출로 생성한다.
- 삭제할 값이 없으면 자료구조를 변경하지 않고 다음 연산으로 넘어간다.
- 실행 후 배열과 AVL 중위 순회 결과의 원소 수 및 모든 원소를 비교한다. 모든 크기에서 `Final Data Match: PASS`가 확인되었다.

## 4. 측정 기준

| 항목 | 측정 기준 |
|---|---|
| 총 수행시간 | 정렬 시작부터 모든 삽입·삭제 완료까지의 `clock()` CPU 시간 |
| 비교 횟수 | 정렬, 삽입 위치/탐색, 삭제 대상 탐색에서 발생한 정수 키 비교 |
| 데이터 이동 | 정수 데이터 값의 복사·대입 횟수. 배열 swap은 임시 변수 포함 3회로 계산 |
| 메모리 | 자료구조 저장 공간 + 연산 목록 + 보조 공간의 추정 최대 크기 |
| 최종 데이터 수 | 모든 연산 완료 후 남은 원소 개수 |

### 측정 시 유의 사항

- 난수 생성과 결과 출력은 측정 시간에서 제외했다.
- 배열의 비교 횟수에는 Quick Sort의 피벗·분할 비교와 삽입·삭제 선형 탐색 비교가 포함된다.
- AVL의 비교 횟수에는 키 탐색과 삽입·삭제 경로 및 회전 유형 결정에 사용된 키 비교가 포함된다. 높이와 균형 인수 계산처럼 키 값과 무관한 제어 비교는 제외한다.
- AVL의 포인터 연결 변경과 높이 갱신은 데이터 이동 횟수에 포함하지 않는다. 새 노드의 키 저장 및 후속자 키 복사는 데이터 이동으로 계산한다.
- 메모리 사용량은 운영체제의 프로세스 메모리 측정치가 아니라 자료구조·연산 목록의 실제 할당 크기와 재귀 스택 프레임 크기(프레임당 64바이트 가정)를 이용한 추정치다. Quick Sort와 AVL의 재귀 스택도 포함한다. 컴파일러·ABI에 따라 실제 스택 프레임 크기는 달라질 수 있다.
- AVL 메모리는 노드당 `sizeof(Node)`를 사용하고, Quick Sort 메모리는 배열 용량을 사용한다. `Operation` 목록은 두 방식 모두 공통 보조 공간으로 포함한다.

## 6. 결과 분석

### 6.1 총 수행시간 및 비교 횟수

초기 정렬만 보면 Quick Sort는 평균적으로 O(n log n)의 효율적인 정렬 알고리즘이다. 하지만 이번 실험의 시간은 초기 정렬에서 끝나지 않고, 이후 n의 20%에 해당하는 삽입·삭제까지 포함한다.

배열은 삽입 위치와 삭제 대상을 선형 탐색하므로 탐색에 O(n)이 걸리고, 삽입·삭제 시 다수의 원소를 이동시켜야 한다. 연산 횟수도 n에 비례해 증가하기 때문에 전체 작업에서 배열의 비교 횟수와 이동 횟수가 빠르게 커졌다.

반면 AVL 트리는 균형을 유지하므로 삽입·삭제 경로가 O(log n)이다. 따라서 데이터가 커질수록 비교 횟수 차이가 크게 벌어졌다. n=20,000에서 배열은 58,645,981회, AVL은 489,009회의 비교를 수행했다.

### 6.2 데이터 이동 횟수

배열은 중간 위치에 삽입할 때 뒤쪽 원소를 이동하고, 삭제할 때도 뒤쪽 원소를 앞으로 당긴다. 따라서 한 번의 연산에서 최악의 경우 O(n)개의 원소 이동이 발생한다.

AVL은 삽입·삭제 과정에서 주로 포인터를 변경해 연결 관계를 조정한다. 포인터 변경은 과제의 데이터 이동 정의에서 제외되므로 키 값의 저장이나 후속자 복사 등 소수의 값 대입만 데이터 이동으로 집계된다. 그 결과 n=20,000에서 배열은 25,099,130회, AVL은 19,938회의 데이터 이동으로 큰 차이가 발생했다.

### 6.3 메모리 사용량

배열은 연속된 정수 공간에 데이터를 저장하므로 원소당 저장 공간이 작고 메모리 접근도 연속적이다. AVL은 각 노드에 키, 중복 횟수, 높이, 왼쪽·오른쪽 포인터를 저장하므로 원소 하나당 필요한 메모리가 더 크다. 노드별 동적 할당 오버헤드까지 고려하면 실제 메모리 차이는 더 커질 수 있다.

실험에서도 n=20,000일 때 배열은 약 129,732 bytes, AVL은 약 654,688 bytes를 사용했다. 즉 AVL은 더 적은 비교와 이동으로 갱신을 수행하는 대신 더 많은 메모리를 사용한다.

### 6.4 데이터 크기 증가에 따른 변화

n이 증가하고 연산 횟수도 n의 20%로 증가하면서 배열의 선형 탐색과 이동 비용이 누적되었다. 특히 큰 n에서 Quick Sort의 초기 정렬 비용보다 이후 삽입·삭제 비용이 전체 결과에 더 큰 영향을 미쳤다.

AVL은 트리 높이가 O(log n)으로 유지되기 때문에 데이터 크기가 증가해도 연산당 탐색 경로가 완만하게 증가했다. 따라서 큰 데이터 크기에서 실행시간, 비교 횟수, 데이터 이동 측면의 이점이 뚜렷해졌다.

### 6.5 삽입·삭제가 반복되는 환경에서 유리한 자료구조

이번 실험 조건처럼 정렬된 상태를 유지하면서 삽입과 삭제가 반복되는 환경에서는 AVL 트리가 더 유리하다. 배열은 조회와 순차 접근, 메모리 효율 측면에서 장점이 있지만 중간 삽입·삭제가 빈번하면 원소 이동 비용이 커진다. AVL은 노드별 메모리 비용이 더 크지만 균형 트리 구조를 이용해 삽입·삭제를 O(log n)에 수행할 수 있다.

따라서 **갱신이 자주 발생하고 데이터가 큰 환경에서는 AVL 트리**, 데이터 변경이 드물고 연속된 메모리와 낮은 저장 오버헤드가 중요한 환경에서는 **정렬 배열**이 적합하다고 판단된다.

## 7. 결론

실험 결과 Quick Sort로 정렬한 배열은 메모리 사용량이 적었지만, 정렬 이후 삽입·삭제를 반복하면서 선형 탐색과 원소 이동이 누적되었다. 반면 AVL 트리는 노드마다 추가 메모리를 사용했지만 균형을 유지하여 삽입·삭제의 비교 횟수와 데이터 이동 횟수를 크게 줄였다.

따라서 정렬 이후 데이터의 삽입과 삭제가 지속적으로 발생하는 상황에서는 AVL 트리가 더 적합하다. 단, 실행시간은 하드웨어·컴파일러·실행 환경에 따라 달라질 수 있으며, 메모리 수치는 본 프로그램에 명시한 추정 기준에 따른 비교값이라는 점을 고려해야 한다.
