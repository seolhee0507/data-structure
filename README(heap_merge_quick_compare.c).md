Heap Sort, Merge Sort, Quick Sort 성능 비교
1. 과제 목표
동일한 무작위 정수 데이터에 대해 힙 정렬(Heap Sort), 병합 정렬(Merge Sort), 퀵 정렬(Quick Sort)을 수행하고 비교 횟수, 실행시간, 최대 추가 메모리 사용량을 비교한다. 퀵 정렬은 첫 번째 원소, 무작위 원소, Median-of-Three의 세 가지 피벗 선택 방법을 사용한다.
2. 데이터 생성 및 실험 조건
항목	설정
데이터 타입	int
데이터 생성	rand() % 100001
정수 범위	0~100,000
중복 값	허용
데이터 크기	1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
난수 시드	srand((unsigned)time(NULL))
정렬 방향	오름차순


각 데이터 크기마다 random_data(n)으로 원본 배열 src를 한 번 생성한다. 각 알고리즘을 실행하기 직전에 memcpy()로 동일한 원본을 작업 배열 work에 복사한다. 따라서 같은 데이터 크기 내의 모든 알고리즘은 같은 입력 데이터에서 시작한다. 난수 시드가 현재 시각이므로 실행할 때마다 입력값과 측정 결과는 달라질 수 있다.
3. 컴파일 및 실행
gcc -std=c11 -O2 -Wall -Wextra heap_merge_quick_compare.c -o heap_merge_quick_compare
./heap_merge_quick_compare
프로그램은 각 데이터 크기마다 알고리즘별 비교 횟수, 실행시간(ms), 추가 메모리(Byte), 정렬 검증 결과를 출력한다. OK는 오름차순 정렬 검증을 통과했다는 뜻이다.
4. 알고리즘 구현 및 비교 횟수
4.1 Heap Sort
- 입력 배열 자체를 최대 힙으로 사용한다. 별도의 힙 저장 배열은 만들지 않는다.
- 마지막 부모 노드부터 루트 방향으로 sift_down()을 수행해 최대 힙을 구성한다.
- 루트의 최댓값을 배열 끝 원소와 교환한 뒤 힙의 유효 범위를 하나 줄이고, 루트에서 다시 힙 속성을 복구한다.
- sift_down()은 재귀가 아닌 반복문으로 구현했다.
- 부모/자식 후보의 정수 값을 비교할 때마다 비교 횟수를 증가시킨다. 자식 노드 존재 여부 등 인덱스 조건 검사는 세지 않는다.
힙 구성은 O(n), 최댓값을 하나씩 꺼내는 과정은 O(n log n)이므로 전체 시간 복잡도는 최선·평균·최악 모두 O(n log n)이다. 입력 배열 내부에서 교환하므로 별도 배열이 필요하지 않으며 보조 공간은 O(1)이다.
4.2 Merge Sort
- 배열을 반으로 나누어 재귀적으로 정렬한 후 정렬된 두 부분 배열을 병합한다.
- 병합 중 양쪽 부분 배열의 현재 원소 값을 비교할 때마다 비교 횟수를 증가시킨다.
- 남은 원소 복사와 인덱스 검사는 비교 횟수에 포함하지 않는다.
- 임시 배열은 데이터 크기 n만큼 한 번 할당하고 병합에 재사용한다.
데이터를 매 단계 절반으로 나누고 각 단계에서 전체 원소를 병합하므로 시간 복잡도는 최선·평균·최악 모두 O(n log n)이다. 임시 배열 O(n)과 재귀 스택 O(log n)이 필요하므로 추가 공간 복잡도는 O(n)이다.
4.3 Quick Sort
Lomuto 분할 방식을 사용한다. 선택한 피벗을 구간의 마지막으로 이동한 후 각 원소와 피벗을 비교해 작은 값(피벗과 같은 값 포함)을 왼쪽으로 보낸다.
- Quick (First): 현재 구간의 첫 번째 원소를 피벗으로 선택한다.
- Quick (Random): 현재 구간에서 무작위 인덱스의 원소를 피벗으로 선택한다.
- Quick (Median3): 현재 구간의 첫 번째·중간·마지막 원소 중 값의 중앙값을 피벗으로 선택한다.
분할 과정의 원소-피벗 비교를 세며, Median-of-Three에서는 피벗 후보 세 값 사이의 비교도 포함한다. 인덱스와 반복문 종료 조건 검사는 제외한다.

평균 시간 복잡도는 O(n log n), 최악 시간 복잡도는 O(n²)이다. 재귀 스택은 평균 O(log n), 최악 O(n)이다. 피벗 선택 방법은 분할 균형에 영향을 준다. 특히 첫 원소 피벗은 이미 정렬되었거나 특정한 패턴의 입력에서 불균형 분할을 만들기 쉽다. 무작위 피벗과 Median-of-Three는 이런 위험을 줄이는 데 도움을 줄 수 있지만 최악의 경우를 완전히 없애지는 않는다.
5. 성능 측정 방법
5.1 숫자 비교 횟수
알고리즘	비교 횟수에 포함되는 연산
Heap Sort	최대 힙 구성 및 각 sift_down()에서 수행하는 부모/자식 값 비교
Merge Sort	병합할 두 부분 배열의 현재 원소 값 비교
Quick (First/Random)	분할 중 각 원소와 피벗의 값 비교
Quick (Median3)	분할 비교 + 첫 번째·중간·마지막 피벗 후보 값 비교


인덱스 계산, 인덱스 범위 검사, 반복문 조건, 재귀 종료 조건, 값 교환은 숫자 비교 횟수에 포함하지 않는다.
5.2 실행시간
timespec_get()을 사용해 정렬 함수 호출 직전과 직후의 시간을 측정하고 밀리초(ms)로 출력한다. 데이터 생성, memcpy() 배열 복사, 정렬 결과 검사, 출력 및 메모리 해제는 측정 구간에서 제외한다. 실행시간은 운영체제 스케줄링, CPU 상태, 컴파일러 최적화 등의 영향을 받으므로 짧은 시간 차이는 반복 실험과 평균값으로 확인하는 것이 바람직하다.
5.3 최대 추가 메모리 사용량
원본 배열과 공통 작업 배열은 모든 알고리즘에 동일하게 필요한 저장 공간이므로 제외한다. 이 프로그램의 메모리 값은 프로세스 전체 메모리를 측정한 값이 아니라, 알고리즘별 추가 메모리를 코드에 정의한 구조체 크기와 재귀 깊이로 계산한 추정치다.
- Heap Sort: 반복형 sift_down()을 사용하므로 재귀 호출 스택이 없다. sizeof(HeapSortAux) + sizeof(SiftDownAux)로 두 함수가 사용하는 보조 지역 변수의 크기를 모델링한다. 이 코드가 실행된 환경에서는 40 Byte로 출력되었다.
- Merge Sort: n * sizeof(int) + max_depth * sizeof(MergeFrame)로 계산한다. 첫 항은 임시 배열, 두 번째 항은 재귀 호출 프레임의 추정치다.
- Quick Sort: max_depth * sizeof(QuickFrame)으로 재귀 호출 프레임의 추정치를 계산한다.
구조체는 지역 변수 및 재귀 프레임의 규모를 일관되게 비교하기 위한 모델이다. 실제 컴파일러가 생성하는 스택 프레임의 정확한 크기와 같다고 보장할 수는 없다. 반환 주소, 레지스터 저장, ABI, 최적화에 따른 차이도 완전히 반영하지 않는다. 따라서 메모리 결과는 실제 RSS나 힙 프로파일링 수치가 아니라 명시된 계산 기준에 따른 비교값으로 해석해야 한다.

7. 결과 분석
7.1 데이터 크기에 따른 비교 횟수
데이터 크기가 증가할수록 세 알고리즘 모두 비교 횟수가 증가했다. Heap Sort와 Merge Sort는 이론적으로 O(n log n)이며, 실험에서도 n이 커질수록 비교 횟수가 대체로 n log n 증가 경향을 보였다. Heap Sort는 최대 힙을 구성한 다음 최댓값을 반복해서 꺼내므로 각 단계에서 부모와 자식 노드를 비교한다. Merge Sort는 각 분할 단계에서 부분 배열을 병합하면서 두 부분 배열의 원소를 비교한다.

이번 실행에서는 Merge Sort의 비교 횟수가 Heap Sort보다 적었다. 이는 병합 과정에서 이미 한쪽 부분 배열이 먼저 소진되면 나머지 원소를 값 비교 없이 복사하기 때문이다. 반면 Heap Sort는 힙의 높이를 따라 내려가며 자식 후보를 확인하는 비교가 반복된다.

퀵 정렬은 피벗 선택 방식에 따라 비교 횟수가 달라졌다. 이번 무작위 입력에서는 Median-of-Three가 n=16,000과 20,000에서 세 퀵 정렬 방식 중 가장 적은 비교 횟수를 기록했다. 다만 Random이 모든 크기에서 항상 유리하거나 First가 항상 불리한 것은 아니다. 실제 결과는 입력값과 피벗 선택 순서에 영향을 받는다.
7.2 실행시간 차이
이번 측정에서는 작은 데이터 크기에서 알고리즘 간 실행시간 차이가 매우 작았고, 일부 크기에서는 순위가 바뀌었다. 예를 들어 n=20,000에서는 Quick (First)가 약 1.068ms, Quick (Median3)가 약 1.045ms, Merge Sort가 약 1.240ms, Heap Sort가 약 1.525ms였다.

실행시간은 비교 횟수만으로 결정되지 않는다. Heap Sort는 배열 안에서 제자리 교환을 수행하지만 힙의 부모·자식 위치를 오가며 접근한다. Merge Sort는 비교 횟수가 적더라도 임시 배열에 기록한 뒤 원본 배열로 다시 복사하는 메모리 이동이 발생한다. Quick Sort는 제자리 분할을 사용해 추가 배열 복사 부담이 적고, 분할이 균형적이면 빠르게 동작할 수 있다. 따라서 비교 횟수가 적은 알고리즘이 항상 가장 빠른 것은 아니다.

측정 시간이 1ms 안팎으로 짧으므로 이 표의 단일 실행 결과만으로 절대적인 속도 우위를 단정하면 안 된다. 더 정확한 분석에는 같은 조건에서 여러 번 실행한 뒤 평균 또는 중앙값을 비교하는 방법이 적절하다.
7.3 메모리 사용량 차이
Heap Sort는 입력 배열 자체를 힙으로 사용하고 반복형 sift_down()을 사용하므로 추가 메모리가 상수 수준이다. 이번 계산 모델에서는 40 Byte로 모든 데이터 크기에서 동일했다.

Merge Sort는 데이터 크기 n에 비례하는 임시 배열을 필요로 한다. 따라서 n이 증가하면 메모리 사용량도 증가했다. n=20,000에서 임시 배열만 80,000 Byte이며 재귀 프레임 추정치를 더해 80,512 Byte로 계산되었다.

Quick Sort는 별도의 임시 배열을 사용하지 않고 재귀 호출 스택을 사용한다. 이번 무작위 입력에서는 계산된 재귀 깊이가 크지 않아 수백 Byte 수준이었다. 다만 피벗 분할이 한쪽으로 치우치면 재귀 깊이가 O(n)까지 커질 수 있고, 그 경우 추가 스택 메모리도 O(n)이 된다.
7.4 피벗 선택 방식
First 방식은 현재 구간의 첫 원소를 피벗으로 사용한다. 입력이 이미 정렬되었거나 역순 등 특정 패턴이면 불균형 분할이 반복되어 최악의 O(n²) 시간이 발생할 수 있다.

Random 방식은 피벗을 무작위로 골라 입력 순서에 따른 편향을 줄인다. 하지만 무작위 선택 자체가 매번 균형 분할을 보장하지 않으므로 실행마다 비교 횟수와 재귀 깊이가 달라질 수 있다.

Median-of-Three는 첫 번째·중간·마지막 원소 중 중앙값을 선택해 극단적인 피벗을 피하려는 방법이다. 피벗 후보 비교가 추가되지만 분할 균형이 개선되면 전체 비교 횟수와 재귀 깊이를 줄일 수 있다. 이번 실행에서는 큰 데이터 크기에서 비교 횟수와 재귀 깊이 측면에서 상대적으로 좋은 결과를 보였다.
7.5 시간·공간 복잡도 요약
알고리즘	최선 시간	평균 시간	최악 시간	추가 공간
Heap Sort	O(n log n)	O(n log n)	O(n log n)	O(1)
Merge Sort	O(n log n)	O(n log n)	O(n log n)	O(n)
Quick Sort	O(n log n)	O(n log n)	O(n²)	평균 O(log n), 최악 O(n)


8. 결론
Heap Sort는 최악의 경우에도 O(n log n)을 보장하고 추가 배열 없이 정렬할 수 있다는 장점이 있다. Merge Sort는 비교 횟수가 효율적이고 입력 상태와 관계없이 O(n log n)을 보장하지만, 임시 배열 때문에 O(n)의 추가 메모리가 필요하다. Quick Sort는 평균적으로 빠르고 추가 배열이 거의 필요하지 않지만 피벗 선택에 따라 성능과 재귀 깊이가 달라진다.

따라서 추가 메모리를 최소화하면서 최악의 시간 복잡도를 보장하려면 Heap Sort가 적합하고, 안정적인 O(n log n) 성능이 중요하며 추가 메모리를 사용할 수 있다면 Merge Sort가 적합하다. 평균적인 실행 속도와 제자리 정렬을 중시한다면 Quick Sort가 유리할 수 있으며, 피벗 선택 전략을 신중하게 선택해야 한다.
