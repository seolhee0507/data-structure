## 3. 순차 탐색과 BST 탐색의 비교

순차 탐색은 배열의 첫 번째 원소부터 탐색 대상과 비교한다. 탐색 대상이 앞부분에 존재하면 비교 횟수가 적지만, 뒤쪽에 존재하거나 배열에 없는 경우에는 많은 비교가 발생한다.

BST 탐색은 현재 노드의 데이터와 탐색 대상을 비교한 후, 값의 크기에 따라 왼쪽 또는 오른쪽으로 이동한다. 따라서 모든 데이터를 차례대로 확인하지 않아도 된다.

이번 실험에서 두 탐색 방법의 비교 횟수 차이는 이러한 탐색 방식의 차이에서 발생한다.

## 4. BST 생성 비용을 고려한 분석

BST는 탐색을 시작하기 전에 노드를 삽입하여 트리를 구성해야 한다. 이 과정에서도 기존 노드와 새로운 데이터의 비교가 발생한다.

따라서 BST의 전체 비교 비용은 다음과 같이 계산하였다.

BST 전체 비용 = BST 생성 비교 횟수 + BST 탐색 비교 횟수

배열은 생성된 숫자를 순서대로 저장하므로 배열에 저장하는 과정의 비교 비용은 이번 탐색 성능 비교에서 제외하였다.

50회의 탐색만 수행하는 경우에는 BST 생성 비용이 탐색 성능의 이점을 줄일 수 있다. 반면 같은 BST를 유지하면서 탐색을 반복하면 생성 비용이 여러 탐색에 분산되므로 BST의 이점이 커질 수 있다.

## 5. 트리 구조에 따른 탐색 성능

BST의 탐색 성능은 트리의 구조에 따라 달라진다.

균형이 잘 잡힌 BST는 왼쪽과 오른쪽의 높이가 비슷하기 때문에 탐색할 때 방문하는 노드 수가 상대적으로 적다.

반면 데이터가 이미 정렬된 순서로 삽입되는 경우에는 한쪽으로 치우친 편향 트리가 만들어질 수 있다. 이 경우 BST임에도 불구하고 탐색 과정에서 많은 노드를 방문하게 되어 순차 탐색과 비슷한 성능을 보일 수 있다.

이번 프로그램은 무작위 순서로 데이터를 삽입하므로 실행할 때마다 트리의 구조와 비교 횟수가 달라질 수 있다.

## 6. 결론

이번 실험을 통해 배열의 순차 탐색과 BST 탐색은 데이터의 저장 및 탐색 방식에 따라 비교 횟수가 달라진다는 것을 확인할 수 있었다.

순차 탐색은 구현이 간단하고 별도의 자료구조 생성 비용이 없지만, 데이터가 많아질수록 탐색 과정에서 많은 비교가 발생할 수 있다.

BST는 노드를 삽입하여 트리를 구성하는 비용이 필요하지만, 트리의 균형이 잘 유지된다면 탐색 과정에서 비교 횟수를 줄일 수 있다.

따라서 탐색 횟수가 적고 데이터가 한 번만 사용되는 경우에는 순차 탐색이 유리할 수 있으며, 동일한 데이터에 대해 탐색을 반복하는 경우에는 BST가 더 효율적일 수 있다.

단, BST의 효율성은 트리의 균형 상태에 따라 달라진다는 점을 고려해야 한다.
