
# Merge Sort와 Quick Sort 성능 비교

## 1. 과제 목표 및 데이터

무작위 정수 데이터에 대해 병합 정렬과 세 가지 피벗 선택 방식의 퀵 정렬을 비교한다. 데이터 크기는 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000이며, 중복 정수를 허용한다. 각 크기에서 하나의 원본 배열을 생성하고, 모든 알고리즘은 `memcpy`로 복사한 동일한 원본의 작업 배열을 정렬한다.

## 2. 컴파일 및 실행

```bash
gcc -std=c11 -O2 -Wall -Wextra sorting_compare.c -o sorting_compare
./sorting_compare
```


## 3. 실험 입력 데이터

### 3.1 데이터 생성 조건

프로그램의 `random_data(n)` 함수는 `rand() % 100001`로 정수를 생성한다.

| 항목 | 설정 |
|---|---|
| 데이터 타입 | `int` |
| 생성 방식 | `rand() % 100001` |
| 정수 범위 | 0~100,000 (양 끝값 포함) |
| 중복 값 | 허용 |
| 데이터 크기 | 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000 |
| 난수 시드 | `srand((unsigned)time(NULL))` |
| 정렬 방향 | 오름차순 |

난수 시드를 현재 시각으로 설정하므로 실행할 때마다 입력 데이터가 달라질 수 있다. 따라서 비교 횟수와 실행시간도 실행마다 달라질 수 있다.

### 3.2 입력 데이터 예시

아래는 데이터 생성 규칙을 보여주기 위한 **설명용 예시 입력 20개**다. 실제 프로그램은 각 데이터 크기에 맞춰 난수 데이터를 생성하므로, 아래 숫자 20개를 그대로 실험에 사용하는 것은 아니다.

```text
42, 7, 100000, 42, 581, 0, 999, 7, 32145, 876,
54, 54, 1200, 99999, 3, 7654, 42, 810, 1200, 17
```

중복 값(예: 42, 7, 54, 1200)이 포함되어 있다. 이처럼 중복 정수가 존재하는 경우에도 모든 알고리즘은 오름차순 정렬을 수행해야 한다.

### 3.3 알고리즘별 입력 데이터 동일성

각 데이터 크기마다 원본 배열 `src`를 한 번 생성한 후, 각 알고리즘을 실행하기 직전에 `memcpy()`로 원본 배열을 작업 배열 `work`에 복사한다.

```c
int *src = random_data(n);

/* 각 알고리즘 실행 직전에 동일한 원본을 복사 */
memcpy(work, src, (size_t)n * sizeof *work);
```

따라서 같은 데이터 크기 안에서는 Merge Sort, Quick (First), Quick (Random), Quick (Median3)이 모두 동일한 원본 데이터에서 시작한다. 단, Random Pivot은 정렬 과정에서 피벗을 무작위로 선택하므로 피벗 선택 순서는 실행마다 달라질 수 있다.

## 4. 알고리즘 구현

### 병합 정렬
배열을 반으로 나누어 재귀적으로 정렬한 뒤 병합한다. 병합 중 양쪽 부분 배열의 원소 값을 비교할 때마다 비교 횟수를 증가시킨다. 남은 원소 복사 및 인덱스 검사는 비교 횟수에 포함하지 않는다. 시간 복잡도는 최선·평균·최악 모두 O(n log n), 추가 공간은 임시 배열 O(n)과 재귀 스택 O(log n)이다.

### 퀵 정렬
Lomuto partition을 사용한다. 피벗을 구간 마지막으로 옮기고, 각 원소와 피벗을 비교해 분할한다.

- Quick (First): 현재 구간의 첫 번째 원소
- Quick (Random): 현재 구간에서 무작위 원소
- Quick (Median3): 첫 번째·중간·마지막 원소 중 값의 중앙값

분할 과정에서 원소와 피벗을 비교할 때마다 카운트한다. Median-of-Three 피벗 선택 과정의 데이터 값 비교도 포함한다. 인덱스 및 반복문 조건 검사는 제외한다. 평균 시간 복잡도는 O(n log n), 최악은 O(n²)이다. 재귀 스택은 평균 O(log n), 최악 O(n)이다.

## 5. 성능 측정 기준

### 비교 횟수

- Merge Sort: 병합 과정의 두 정수 값 비교
- Quick Sort: 분할 과정의 원소-피벗 비교
- Median-of-Three: 피벗 후보 값끼리의 비교도 포함
- 인덱스, 반복문 종료 조건, 재귀 종료 조건, 난수 인덱스 계산은 제외

### 실행시간

`timespec_get()`으로 정렬 함수 직전과 직후를 측정하고 밀리초(ms)로 출력한다. 데이터 생성, 배열 복사, 정렬 결과 검사, 출력 및 메모리 해제 시간은 제외한다. 실행시간은 운영체제 스케줄링, CPU 상태, 컴파일러 최적화 등에 따라 달라질 수 있다.

### 메모리(Byte)

출력되는 메모리는 프로파일러로 측정한 실제 프로세스 메모리가 아니라, 코드에 정의한 논리적 재귀 프레임 크기와 최대 재귀 깊이를 이용한 추정치다. 공통 원본 배열과 작업 배열은 제외한다.

- Merge Sort: `n * sizeof(int)` 임시 배열 + `max_depth * sizeof(MergeFrame)`
- Quick Sort: `max_depth * sizeof(QuickFrame)`

`MergeFrame`과 `QuickFrame`은 재귀 호출 프레임의 규모를 일관되게 추정하기 위한 구조체다. 따라서 실제 컴파일러가 생성한 스택 프레임의 정확한 크기와 같다고 보장할 수 없다. 반환 주소, 레지스터 저장, 컴파일러 최적화 및 ABI에 따른 차이는 완전히 반영하지 않는다. 보고서에는 이 점과 계산식을 함께 명시한다.

## 6. 출력 및 정렬 검증

각 데이터 크기에서 네 알고리즘의 비교 횟수, 실행시간, 메모리 추정치와 `Check`를 출력한다. `OK`는 결과 배열이 오름차순임을 뜻하고 `FAIL`은 정렬 구현을 재검토해야 함을 뜻한다. 실제 수치는 실행 환경과 난수 데이터에 따라 달라지므로 임의의 결과를 미리 기입하지 않는다.

## 7. 결과 분석 방향

1. **비교 횟수와 데이터 크기:** 병합 정렬은 각 단계에서 전체 원소를 병합하므로 O(n log n)에 비례하는 경향을 보인다. 퀵 정렬은 분할이 균형적이면 평균 O(n log n)이지만 한쪽으로 치우친 분할이 반복되면 O(n²)에 가까워질 수 있다.
2. **실행시간:** 비교 횟수 외에도 재귀 호출, 메모리 접근, 임시 배열 복사, 피벗 선택 비용이 영향을 준다. 병합 정렬은 임시 배열로 병합하고, 퀵 정렬은 제자리 분할을 수행하는 대신 분할 및 재귀 비용이 발생한다.
3. **메모리:** 병합 정렬은 O(n)의 임시 배열이 필요하다. 퀵 정렬은 별도 전체 배열은 없고 재귀 스택을 사용하므로 평균 O(log n), 최악 O(n)이다.
4. **피벗 선택:** First는 선택 비용이 작지만 입력 순서에 따라 나쁜 분할을 만들 수 있다. Random은 입력 순서에 덜 민감하도록 무작위 선택을 하지만 난수 생성 비용이 있다. Median-of-Three는 세 후보의 추가 비교가 발생하지만 극단적인 피벗을 피하는 데 도움을 줄 수 있다.
5. **중복 값:** 본 구현의 분할 조건은 `<= pivot`이므로 중복 값이 많을 때 분할 균형에 영향을 줄 수 있다.

실험 입력은 무작위 정수이므로 세 피벗 방식의 차이가 정렬/역순 입력에서처럼 크게 나타나지 않을 수 있다. 결과를 바탕으로 실제 비교 횟수와 실행시간의 추세를 기술하고, 이론적 복잡도와 일치하는지 분석한다.
