과제 10: 정렬 알고리즘의 성능 및 안정성 비교
1. 과제 개요
본 프로그램은 C언어로 선택 정렬(Selection Sort), 일반 버블 정렬(Bubble Sort), 조기 종료 버블 정렬(Bubble Sort with Early Termination), 삽입 정렬(Insertion Sort)을 구현하고 성능 및 안정성을 비교한다.

각 데이터는 key1, key2, original_index 세 항목으로 구성된다.
- key1: 정렬 기준이 되는 첫 번째 정수 키
- key2: 데이터와 함께 이동하지만 정렬 기준으로 사용하지 않는 두 번째 정수 키
- original_index: 입력 당시의 순서를 기록하여 안정성을 검증하기 위한 번호
데이터 수는 10,000개이며, Key 1과 Key 2는 각각 rand() % 1000001을 이용해 0부터 1,000,000까지 생성한다. 무작위 데이터 실험은 NUM_TRIALS에 지정된 100회 반복한다.

2. 성능 측정 기준
2.1 숫자 비교 횟수
compare_keys() 함수가 호출될 때마다 비교 횟수를 1 증가시킨다. 이 함수는 두 데이터의 key1만 비교한다. 따라서 두 번째 키나 원래 입력 순서는 정렬 기준 비교에 포함되지 않는다.

정렬 함수의 반복문 인덱스 검사나 종료 조건 검사는 비교 횟수에 포함하지 않는다. 정렬 결과 확인용 비교가 별도로 실행된다면 정렬 알고리즘 내부 카운터에는 포함되지 않는다.
2.2 데이터 이동 횟수
데이터 구조체 DataItem 전체를 다른 위치 또는 임시 변수에 대입할 때 1회로 센다. key1, key2, original_index는 하나의 구조체로 함께 이동한다.
- 교환: 임시 변수에 저장 1회, 배열 원소 대입 2회로 총 3회
- 선택 정렬: 최솟값 위치가 현재 위치와 다를 때만 교환하므로 교환마다 3회
- 버블 정렬: 인접한 두 데이터가 교환될 때마다 3회
- 삽입 정렬: current에 저장하는 대입, 기존 데이터를 오른쪽으로 미는 대입, 최종 위치에 넣는 대입을 각각 계산
입력 배열을 memcpy()로 복사하거나 데이터를 생성하고 실험용 입력을 준비하는 과정은 정렬 함수의 이동 횟수에 포함하지 않는다.
3. 구현한 정렬 알고리즘
3.1 선택 정렬 (Selection Sort)
현재 정렬 위치부터 배열 끝까지 탐색해 key1이 가장 작은 데이터의 위치를 찾고, 그 데이터를 현재 위치와 교환한다. 입력 데이터의 초기 정렬 상태와 관계없이 비교 횟수는 다음과 같다.
\[
\frac{n(n-1)}{2}
\]
데이터 수가 10,000개일 때 한 번의 정렬에서 비교 횟수는 49,995,000회다. 선택 정렬은 교환 횟수가 상대적으로 적지만, 동일한 키를 가진 데이터의 상대 순서가 바뀔 수 있어 일반적으로 안정 정렬이 아니다.
3.2 일반 버블 정렬 (Bubble Sort)
인접한 두 데이터의 key1을 비교한다. 앞 데이터의 키가 더 크면 두 데이터를 교환한다. 이 코드에서는 조기 종료 조건 없이 정해진 모든 순회를 수행한다. 따라서 데이터 수가 같으면 입력 순서에 관계없이 비교 횟수는 49,995,000회다.
3.3 조기 종료 버블 정렬 (Bubble Sort with Early Termination)
일반 버블 정렬과 같은 방식으로 비교하고 교환하지만, 각 순회에서 교환이 발생했는지를 swapped 변수로 확인한다. 한 번의 순회에서 교환이 없으면 이미 오름차순으로 정렬된 것으로 판단하고 반복을 종료한다.

이미 정렬된 데이터에서는 첫 번째 순회만 수행하므로 비교 횟수가 크게 줄어든다. 반대로 역순 데이터에서는 많은 교환이 필요하므로 조기 종료 효과가 제한적이다.
3.4 삽입 정렬 (Insertion Sort)
정렬되지 않은 구간에서 데이터 하나를 current에 저장하고, 정렬된 구간에서 current.key1보다 큰 데이터를 오른쪽으로 이동시킨 후 빈 위치에 삽입한다.

일반 실험에는 arr[j].key1 > current.key1 조건을 사용하는 버전이 사용된다. 이 조건은 키가 같은 데이터를 이동시키지 않으므로 안정성을 유지한다. 별도의 안정성 테스트에서는 >와 >=를 모두 실행해 차이를 확인한다.
4. 무작위 데이터 100회 실험
각 반복에서 generate_random_data()를 호출해 10,000개 데이터를 생성한다. 그 다음 동일한 base_data를 memcpy()로 work_data에 복사해 각 정렬 알고리즘에 제공한다. 따라서 같은 반복 안에서 알고리즘마다 다른 난수 입력을 사용하는 문제는 없다.

프로그램은 각 알고리즘에 대해 총 비교 횟수와 총 이동 횟수를 누적한다. 출력되는 평균 비교 횟수와 평균 이동 횟수는 누적값을 100으로 나눈 정수 값이다. 따라서 소수점 이하 평균은 출력되지 않는다.


선택 정렬과 일반 버블 정렬은 한 번에 49,995,000회 비교하므로 100회 실험의 총 비교 횟수는 각각 4,999,500,000회다. 조기 종료 버블 정렬은 정렬이 완료되는 순회 시점에 따라 비교 횟수가 달라진다. 삽입 정렬은 데이터의 초기 순서와 역전의 수에 따라 비교 및 이동 횟수가 달라진다.
5. 입력 데이터의 정렬 상태에 따른 실험
상태별 테스트를 위해 프로그램은 새로운 무작위 데이터 10,000개를 생성한 뒤 qsort()로 Key 1 기준 오름차순 정렬하여 기준 데이터 ref_data를 만든다. qsort()는 실험 입력을 준비하는 데에만 사용하며, 과제의 세 정렬 알고리즘을 대체하지 않는다.
5.1 이미 정렬된 데이터 (Sorted Data)
오름차순으로 정렬한 기준 데이터의 복사본을 사용한다. 선택 정렬은 모든 구간을 탐색하므로 비교 횟수가 줄어들지 않는다. 일반 버블 정렬도 고정된 순회를 수행하므로 비교 횟수가 동일하다. 조기 종료 버블 정렬은 첫 순회에서 교환이 없음을 확인한 뒤 종료한다. 삽입 정렬은 이미 올바른 위치에 있는 데이터를 확인하므로 이동이 적다.
5.2 역순 데이터 (Reverse-Sorted Data)
오름차순 기준 데이터의 레코드 순서를 반대로 뒤집어 내림차순 데이터를 만든다. 선택 정렬과 일반 버블 정렬의 비교 횟수는 데이터 순서에 관계없이 동일하지만 교환 및 이동 횟수는 입력 순서의 영향을 받는다. 버블 정렬과 삽입 정렬은 역순 입력에서 많은 데이터 이동이 발생한다. 조기 종료 버블 정렬도 정렬이 완료될 때까지 교환이 계속되므로 조기 종료의 이점이 크지 않다.
5.3 부분 정렬 데이터 (Partially Sorted Data)
부분 정렬 데이터는 오름차순으로 정렬된 기준 데이터에서 시작해 무작위로 선택한 두 인덱스의 데이터를 교환하는 방식으로 만든다. 코드에서는 다음과 같이 교환 횟수를 정한다.
int swaps = (int)(DATA_COUNT * 0.05);
데이터가 10,000개이므로 두 위치를 교환하는 작업을 500회 수행한다. 따라서 이 과제 구현의 부분 정렬 데이터는 정렬된 배열에 500회의 무작위 pairwise swap을 적용한 데이터다. 교환으로 인해 실제로 영향을 받는 서로 다른 인덱스 수는 중복 인덱스 선택에 따라 달라질 수 있다.

선택 정렬은 입력 상태와 관계없이 비교 횟수가 일정하다. 버블 정렬과 삽입 정렬은 교환으로 인해 생긴 역전의 위치와 수에 따라 비교 및 이동 횟수가 달라진다. 일반적으로 역전이 적은 데이터에서는 삽입 정렬이 유리하고, 조기 종료 버블 정렬은 교환이 더 이상 발생하지 않는 순회가 언제 나타나는지에 영향을 받는다.

6. 안정성 검증
안정 정렬이란 정렬 기준인 key1이 같은 데이터들의 원래 상대 순서를 정렬 후에도 유지하는 정렬이다. 코드에서는 각 데이터에 original_index를 저장하고, 정렬 후 인접한 데이터의 key1이 같을 때 앞 데이터의 original_index가 뒤 데이터보다 큰지 확인한다. 원래 순서가 뒤집혔다면 Unstable, 그렇지 않다면 Stable을 반환한다.


6.1 선택 정렬
선택 정렬은 최솟값을 현재 위치로 교환하는 과정에서 같은 Key 1을 가진 데이터들의 상대 순서를 바꿀 수 있다. 따라서 일반적인 선택 정렬은 불안정 정렬이다. 프로그램은 실제 정렬 결과를 verify_stability()로 확인하고 Stable 또는 Unstable을 출력한다.
6.2 버블 정렬
버블 정렬은 앞의 Key 1이 뒤의 Key 1보다 클 때만 교환한다. Key 1이 같은 두 데이터는 서로 교환하지 않으므로 안정성을 유지한다.
6.3 삽입 정렬의 >와 >= 비교
- >: 앞 데이터의 Key 1이 현재 데이터보다 클 때만 오른쪽으로 이동한다. 같은 키의 데이터는 이동시키지 않으므로 안정적이다.
- >=: 앞 데이터의 Key 1이 현재 데이터와 같아도 오른쪽으로 이동한다. 새로운 데이터가 기존의 같은 키 데이터보다 앞에 삽입될 수 있어 상대 순서가 뒤집히며 불안정해질 수 있다.
프로그램은 동일한 테스트 데이터를 각 알고리즘에 복사해 정렬한 후 안정성을 각각 출력한다. 실제 출력 결과를 README에 기록하고, 원래 입력 순서가 어떻게 달라졌는지 비교해 설명한다.
7. 버블 정렬 조기 종료의 영향
일반 버블 정렬은 정해진 모든 순회를 수행하므로 데이터가 이미 정렬되어 있어도 비교를 계속한다. 조기 종료 버블 정렬은 한 순회에서 교환이 발생하지 않으면 반복을 종료한다.

따라서 이미 정렬된 입력에서는 일반 버블 정렬이 49,995,000회의 비교를 수행하는 반면 조기 종료 버블 정렬은 첫 순회에서 9,999회의 비교만 수행한다. 역순 입력에서는 각 순회에서 교환이 발생하므로 조기 종료 조건의 효과가 제한적이다. 무작위 입력에서는 교환이 없는 순회가 언제 나타나는지에 따라 비교 횟수가 달라진다.
8. 결론 
본 실험에서는 10,000개의 데이터를 사용해 선택 정렬, 일반 버블 정렬, 조기 종료 버블 정렬, 삽입 정렬의 비교 횟수와 데이터 이동 횟수를 측정하였다. 선택 정렬과 일반 버블 정렬은 입력 데이터의 초기 정렬 상태와 관계없이 비교 횟수가 일정했다. 반면 조기 종료 버블 정렬과 삽입 정렬은 데이터의 정렬 상태에 따라 비교 횟수가 달라졌다. 정렬 데이터에서는 조기 종료 버블 정렬이 교환 없는 첫 순회 이후 종료하여 비교 횟수를 줄였으며, 삽입 정렬도 적은 이동으로 정렬을 마쳤다. 역순 데이터에서는 교환과 이동이 많이 발생했다. 안정성 검증에서는 버블 정렬과 삽입 정렬의 > 버전이 동일 키의 상대 순서를 유지하는지 확인했고, 삽입 정렬의 >= 버전은 같은 키도 이동시키기 때문에 불안정해질 수 있음을 확인했다. 최종 결론에는 실제 측정값을 바탕으로 알고리즘별 차이를 설명한다.
